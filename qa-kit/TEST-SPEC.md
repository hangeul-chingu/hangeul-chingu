# 검사 명세 (V599 기준) — "66"이 세는 것

실행 단위 = 팩 1개 × 화면 크기 1개. 한 실행은 1·2·3일차를 모두 진행하며, 하루마다 22개 검사를 셉니다(22 × 3일 = 66).

하루 22개의 내역
1. 첫 알아보기 문항에서 오답 하나를 눌렀을 때 "아직이에요"와 그 오답의 설명(whys)이 JSON과 일치 (1개)
2. 알아보기 5문항: 정답을 눌렀을 때 "맞았어요" + 해설(explain) 표시 (5개)
3. 첫 떠올리기 문항에서 엉뚱한 입력 시 "아직이에요" 안내 (1개)
4. 떠올리기 5문항: 인정 답 목록(answers)을 문항마다 번갈아 입력해 정답으로 인정되는지 (5개)
5. 말하기 5문항: 문장 입력 후 "내 문장 점검" 화면과 "스스로 점검" 표시 (5개)
6. 말하기 5문항: 참고 예시(examples) 표시 (5개)

실행 중 상시 확인(실패할 때만 기록): 가로 넘침(문항·떠올리기·말하기 점검 화면), 페이지 오류(콘솔 pageerror), 하루 완료 화면 도달, 다음 날 열림(날짜를 하루씩 앞당겨 확인).
실행 단위: culture01~13 × (휴대폰 360px, PC 1280px) = 26개 실행 가능. V599 확인 때는 휴대폰 13개, PC 7개(culture07~13), 390px 1개(culture08) = 21개 실행을 돌렸고 모두 66/66.

## 이 검사가 하지 않는 것 (NOT TESTED)
- 알아보기 4개 보기 전부의 오답 이유 대조 (첫 문항의 오답 1개만 대조)
- 떠올리기의 인정 답 전부·공백/띄어쓰기 변형·거절되어야 하는 답의 거절 확인 (문항당 인정 답 1개만 입력)
- 새로고침 후 진도 보존, 자정·타임존·서버 날짜 경계 (날짜는 브라우저 시계를 앞당겨 흉내만 냄)
- 글자 크기 200% 확대, 보기 버튼 겹침, 밑줄 고립 등 세부 레이아웃
- 네트워크 실패·로그인 만료·저장 실패 시 사용자 안내와 재시도
- 앱 버전 문자열(APP_VERSION)의 실제 렌더링
- 실제 운영 배포, 실제 Firebase 인증·저장, 실기기(아이폰·안드로이드), 마이크


## 업데이트 (화면 증거·P1 확대)
- 하루 검사 수가 22 → 27개로 늘었습니다(실행당 81개). 보고서는 실행당 78개 미만이면 실패로 판정합니다.
- 알아보기: 문항마다 서로 다른 오답을 눌러 그 보기의 오답 이유를 JSON과 대조(앞 2문항은 오답 2개씩, 3문항째부터 정답+해설). 보기 번호는 문항·화면 크기에 따라 돌아갑니다. 4개 보기 전부를 모든 문항에서 확인하는 것은 아닙니다.
- 떠올리기: 인정 답을 문항마다 바꿔 입력. PC는 띄어쓰기를 모두 제거한 형태, 휴대폰은 끝에 마침표를 붙인 형태로 입력해 정규화 통과 여부 확인. 빈 입력은 확인 불가 확인.
- 휴대폰(360/390) 실행은 하루마다 화면 6장(JPG) 저장: 알아보기 문제, 오답 해설, 떠올리기 문제, 떠올리기 오답, 떠올리기 인정, 내 문장 점검. 일차 완료 화면(PNG)은 기존대로.
- 여전히 하지 않는 것: 새로고침 후 진도, 날짜 경계, 글자 200%, 네트워크·로그인·저장 실패(P2~P4), 실기기, 실제 Firebase, 마이크.


## 업데이트 2 — P2·P3·P4 추가 검사 (extra.mjs, 팩당 1회, 휴대폰 360px)
앱 코드를 읽어 확인한 사실에 맞춘 기준입니다: 진도는 문제를 풀 때마다 저장되고, 저장이 실패하면 "저장하지 못했어요" 안내가 뜨며 다음 문제에서 다시 저장합니다. 이 기준을 앱이 바꾸면 이 검사도 함께 고쳐야 합니다.
- P2-A: 알아보기 2문항을 푼 뒤 새로고침 → 같은 일차·같은 문항 번호(예 1일째 3/15)에서 이어지는지.
- P2-B: 1일차를 끝낸 날은 2일차가 잠기는지, 한국 시간 자정 2분 전에는 잠금 유지, 2분 후에는 2일차가 열리는지. (브라우저 시계를 바꾸는 모의 검사이며 실제 서버·Firestore 규칙은 아님)
- P4-A: 저장을 막으면 "저장하지 못했어요" 안내가 그 화면에 표시되고, "저장 완료" 같은 거짓 표시가 없고, 저장이 회복되면 안내가 사라지는지.
- P3: 브라우저 200% 확대를 폭 180px로 흉내 내어, 알아보기 보기 4개·다시 해 보기 버튼·떠올리기 입력창·확인 버튼이 화면 안에 있는지, 화면 오른쪽 밖으로 나간 요소가 없는지. 밑줄 단독 줄바꿈 자체는 실패로 보지 않음.
- 팩당 17개 검사, 보고서는 15개 미만이면 실패로 판정.
- 하지 않는 것(NOT TESTED): 실제 Firebase 저장, 로그인 만료·로그아웃·권한 거부(P4-B), 다른 기기·다른 사용자 기록 혼선, 실제 타임존·기기 시계 변경, 실제 글자 크기 설정(OS), 키보드 가림, 실기기.


## 업데이트 3 — pack4 (검사 기준 버전 pack4-lock-v1)
- 버전별 기대치는 expect.json에 둡니다(실행당 81개, 추가 검사 17개, 필수 CASE 목록, 화면 캡처 최소 장수). 앱 동작이 바뀌면(예: A안 연속 학습) expect.json과 이 문서를 함께 고칩니다.
